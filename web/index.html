📋The whiteboard with a limited number of sticky notes

🧠
Imagine your brain is a small whiteboard. Every time you learn something new — a friend's name, a phone number, a fact — you write it on a sticky note and stick it on the board.
📝
If the board has plenty of empty space, every note is easy to read. You can look at any note and know exactly what it says. Perfect memory.
😵
But the whiteboard doesn't grow. If you keep sticking on more and more notes, they start to overlap and cover each other up. Now when you look for one note, you might read the wrong one underneath it by mistake.
That's exactly what happens inside the AI system below. 👇

🐉What does this have to do with the dragon?

🐲
Dragon Hatchling (BDH) is a real AI system, built by a company called Pathway, that works kind of like a brain instead of a normal computer program. Instead of writing every single thing it reads onto an ever-growing pile of paper (like most AI does), it uses the same "sticky notes on a small whiteboard" trick you just tried — connections between its "neurons" get stronger when something matters, like writing on a sticky note, and old ones fade or blend together if too much gets crammed in.
✨
One important twist: BDH only "writes" using a small number of very clear, spread-out notes (not a huge messy pile all bunched together). You can test why that helps too — try the technical view and play with the "sparsity" slider!

🎓What you just learned

✅ A small memory can hold information from a never-ending stream, without ever needing more space.
✅ The trade-off: if you cram in too much, things start blending together and it makes mistakes.
✅ Real AI (BDH) uses this exact idea — and uses a trick (keeping notes small and spread out) to delay the mix-ups as long as possible.

In your own words — why does a whiteboard with too many sticky notes get confusing?

Central claim: A fixed-size n×d associative state, written one token at a time with a single Hebbian outer-product update S ← S + φ(k)vᵀ, can retrieve key→value associations from a sequence of unbounded length without allocating new memory per token — but once the number of associations written exceeds roughly the key dimension n (its capacity), retrieval accuracy degrades because overlapping sparse keys interfere with each other in the same fixed slots.

2What's actually happening (mechanism)

Write (one Hebbian step per token, memory size never changes):

k = sparse_nonneg_key(n)    S ← S + φ(k) · onehot(class)ᵀ,   φ = ReLU

Read (associative recall from a cue, no search over history):

scores = φ(cue) · S    prediction = argmax(scores)

This is exactly the "linear attention as fast weights" view: instead of comparing a query against every past key (softmax attention, O(N) memory and O(N) compute per query), the past is compressed additively into one matrix S. Reading is one dot product against whatever S currently holds.

5Memory cost: fixed state vs. growing KV-cache

The associative state's parameter count never changes as N grows — that is the whole appeal. A conventional attention KV-cache keeps perfect recall (accuracy always 1.0) by paying for it in memory that grows linearly with sequence length. The trade the claim is about: constant memory vs. interference, against growing memory vs. perfect recall.

6The BDH connection

Real published mechanism The Dragon Hatchling paper (Kosowski et al., 2025) describes BDH's attention as arising from a local, biologically-plausible edge-reweighting rule that combines Hebbian learning with modus-ponens–like inference over a graph of neuron particles, rather than dense query/key/value matrix multiplication. Its GPU-friendly formulation, BDH-GPU, is explicitly built from ReLU-low-rank transformations with linear attention and non-negative, sparse neuron activations (reported around ~5% active at a time) — the same three ingredients (Hebbian outer-product writes, ReLU non-negativity, and sparsity) that this toy memory uses above.

Our educational toy model is a minimal, from-scratch instance of that mechanism at a scale you can inspect (n in the hundreds, not BDH's trained parameter count). It is not the official BDH implementation, was not trained on language data, and makes no claim to reproduce BDH's reported benchmark numbers.

Real published result BDH-CQ (Pathway, 2026), a later system in the BDH family, stores task demonstrations by updating recurrent memory at inference time — additively, per demonstration — rather than by a gradient step, and reasons over that memory in a continuous latent workspace instead of a written chain of thought. On the public ARC-AGI-1 benchmark, Pathway reports a 150M-parameter BDH-CQ configuration reaching 29.5% pass@2 at roughly $0.0007 per task, which independent testers (Bielik AI and NYU, per Pathway's own reporting) reproduced. This is a developer-reported benchmark result, independently reproduced on that specific benchmark — not a claim about deployment, and not evidence about performance on other tasks.
